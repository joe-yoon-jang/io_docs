# 도커란?

컨테이너를 쉽게 사용할 수 있게 만들어진 오픈소스 프로젝트입니다. 도커 컴포즈, 레지스트리, 도커허브 등 여러 가지가 있지만 일반적으로 도커라고 하면 도커 엔진 혹은 도커에 관련된 모든 프로젝트를 의미합니다.

## 가상머신과 도커 컨테이너

- 기존의 가상화 기술은 하이퍼바이저를 이용해 여러개의 운영체제를 하나의 호스트에서 생성해 사용하는 방식으로 여러 개의 운영체제가 독립된 공간과 시스템 자원을 할당받아 가상 머신이라는 단위로 구별되어 사용됩니다.
- 이러한 방식은 일반 호스트에 비해 성능의 손실이 발생합니다.
- 하지만 도커 컨테이너는 가상화된 공간을 생성하기 위해 리눅스의 자체 기능을 사용해서 프로세스 단위의 격리 환경을 만들기 때문에 성능 손실이 거의 없습니다.
- 컨테이너에 필요한 커널은 호스트의 커널을 공유해 사용합니다.

## 도커의 필요성

### 애플리케이션의 개발과 배포

- 도커 컨테이너는 호스트 os위에서 실행되는 격리된 공간입니다.
- 즉 독립된 환경을 보장받을수 있습니다.
- 도커 이미지라고 하는 일종의 패키지로 만들어 운영서버에 전달하기만하면 배포됩니다.
- 의존성등도 걱정할필요 없이 컨테이너로 똑같이 복제할수 있기 때문에 개발/운영 환경의 통합이 가능해집니다.


### 독립성과 확장성

- 소프트웨어의 여러 모듈이 상호 작용하는 로직을 하나의 프로그램 내에서 구동시키는 방식을 모놀리스 애플리케이션라고 합니다.
- 서비스가 거대해질수록 확장성과 유연성이 줄어든다는 단점이 있어 마이크로 서비스 구조로 대체하고있습니다.

### AWS

- EC2 서비스에서 리눅스 환경을 사용가능하고 여기서 도커를 사용할수도 있습니다.

# 도커 엔진

도커 엔진에서 사용하는 기본단위는 이미지와 컨테이너입니다.

## 도커 이미지

- 이미지는 컨테이너를 생성할 때 필요한 요소이며 가상머신을 생성할때 사용하는 ISO 파일과 비슷한 개념입니다.
- 이미지 이름은 기본적으로 [저장소이름]/[이미지이름]:[태그]의 형태로 구성됩니다.
    - alicek106/ubuntu:14.04
    - ubuntu:latest (이미지이름:태그)
- 저장소: 이미지가 저장된 장소를 의미하며 기본적으로 도커 허브의 공식 이미지를 의미합니다.
- 이미지 이름: 위 우분투와 같이 해당 이미지가 어떤 역할을 하는지 나타냅니다.
- 태그: 이미지의 버전관리 혹은 리비전 관리에 사용됩니다. 생략시 이미지의 태그를 latest로 인식합니다.

## 도커 컨테이너

- 이미지로 컨테이너를 생성하면 해당 이미지의 목적에 맞는 독립된 공간이 생성되며 이것이 컨테이너입니다.
- 컨테이너는 이미지를 읽기 전용으로 사용하되 이미지에서 변경된 사항만 컨테이너 계층에 저장합니다.

### 도커 컨테이너 명령어

```bash
docker run -i -t ubuntu:14.04
```

- 위 명령어로 도커 컨테이너를 생성 및 실행하기 위한 우분투 이미지를 내려받고 컨테이너 내부로 들어가는 명령을 실행하게됩니다.

```bash
docker pull centos:7
docker images
```

- 위 명령어로 이미지를 내려받고 이미지의 리스트를 확인합니다.

```bash
docker create -i -t --name mycentos centos:7
docker start mycentos
docker attach mycentos
```

- 위 명령어는 creat로 컨테이너를 생성하고 start로 컨테이러를 실행하고 attach로 내부로 들어갑니다.


```bash
docker ps
```

- ps는 정지되지 않은 컨테이너만 실행합니다. -a 옵션을 추가해서 정지된 컨테이너를 포함한 모든 컨테이너를 확인할수 있습니다.

```bash
docker stop mycentos
docker rm mycentos
```

- rm은 도커 컨테이너를 삭제합니다. run 중인 컨테이너는 삭제할수 없기때문에 중단 시키고 삭제작업을합니다. 
    - f옵션으로 실행 중인 컨테이너도 삭제가 가능합니다.

## 컨테이너 외부 노출

- 컨테이너는 가상머신과 동일하게 가상 ip주소를 할당 받습니다.
    - 기본적으로 172.17.0.X
- 추가 설정을 하지 않는다면 로컬 호스트에서만 컨테이너에 접근이 가능합니다. 
- 외부에 노출하기 위해서는 포트바인딩을 사용합니다.
    - -p 7777:80 위 옵션은 호스트7777 포트와 컨테이너 80포트와 연결합니다.

## 도커 볼륨

- 도커 이미지로 컨테이너를 생성하면 이미지는 읽기 전용이되며 컨테이너의 일부 영역에만 정보를 저장해서 보존합니다.
- 하지만 컨테이너를 삭제하면 저장된 데이터는 삭제합니다. 이에 컨테이너의 데이터를 영속적 데이터로 활용할 수 있는 몇 가지 방법이 있으며 그중 하나로 볼륨이 있습니다.
- -v /home/db:/var/lib/mysql
    - 위 옵션은 호스트 /home/db 디렉토리를 컨테이너의 /var/lib/mysql과 공유한다는 뜻입니다.
- 컨테이너가 삭제되어도 /home/db 데이터는 그대로 남아있습니다.
- -v 옵션으로 볼륨 컨테이너를 생성하고 --volume-from을 사용하면 볼륨 컨테이너를 사용하여 home/db를 공유 받을수있습니다.

## 도커 네트워크

- 컨테이너를 생성하면 기본적으로 docker0 브리지를 통해 외부와 통신할수 있는 환경을 사용할수 있습니다. 
- 도커가 기본적으로 제공하는 대표적인 네트워크 드라이버로는 브리지, 호스트, 논, 컨테이너, 오버레이가 있습니다.

```bash
docker network create --driver bridge mybridge

docker run -i -t --name mynetwork_container \
--net mybridge \
ubuntu:14.04

docker network disconnect mybridge mynetwork_container
docker network connect mybridge mynetwork_container
```
- 위 명령어와 같이 네트워크를 생성하고 컨테이너테 붙이고 연결을 끊을수 있습니다.

- --net host 명령어를 사용하여 호스트의 네트워크 환경을 그대로 사용할수도 있습니다.
- --net none 네트워크는 아무런 네트워크를 사용하지 않는것을 뜻합니다.
- --net container:container_name 다른 컨테이너의 네트워크 네임스페이스 환경을 공유합니다. 공유되는 속성은 내부 ip 네트워크 인터페이스의 맥주소등입니다.
    - 위와 같이 공유하면 내부 아이피를 새로 할당받지 않으며 veth가상 네트워크 인터페이스도 생성하지 않습니다.
- --net-alias 브리지 타입의 네트워크를 특정 호스트 이름으로 컨테이너 여러개에 접근할수 있습니다.

## 컨테이너 로깅

```bash
docker logs mysql
```

- mysql 컨테이너의 로그를 확인합니다.
- logs --tail 2
    - 로그 끝에서 2줄 확인합니다.
- logs --since 1474765979
    - 특정 시간 이후 로그를 확인합니다.
- logs -f -t mysql
    - t 로 타임스탬프를 찍으며 f로 스트림으로 로그를 확인합니다.
- 기본적으로 로그는json형태로 컨테이너 아이디 경로 밑에 저장됩니다.
    - 로그는 남은 저장곤간을 전부 사용할수도있으므로 사이즈 제한등을 지정하여 사용가능합니다.

## 컨테이너 자원 할당

- 기본적으로 컨테이너는 호스트의 전체 리소스를 사용가능하여 제한을 줄수있습니다.    
- 메모리, cpu, block i/o 대역, 저장공간 제한등이 가능합니다.

## 도커 이미지

- 도커 이미지는 도커 이미지를 레이어 단위로 관리합니다. a -> a1 -> a2 등의 레이어를 갖을수 있습니다.
    - a1이미지를 삭제하더라도 a2 이미지가 있으면 실제 레이어는 유지하여 삭제하지않습니다. a2를 지우면 a1,a2를 비로소 삭제합니다.
- 도커 이미지를 파일로 저장 및 로드할수 있습니다.
